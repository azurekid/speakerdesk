# Verify a change before it ships

CI (`.github/workflows/deploy.yml`, job `check`) runs `npm run typecheck` and `npm run lint` on every push to `main`, and a push to `main` **deploys to production**. Run this gate locally first.

## Steps

Run from the repo root and stop at the first failure — fix it, then rerun from that step.

1. **Typecheck** — `npm run typecheck`
   - This is `next typegen && tsc --noEmit`. `PageProps`, `LayoutProps` and `RouteContext` are global types generated by `next typegen`; never import them and never remove typegen from the script.
2. **Lint** — `npm run lint`
   - **What's new** — `node scripts/whats-new-check.mjs`: every release item has a screenshot, no em dashes, releases newest first. See the `whats-new` skill to fix a failure.
3. **Prisma schema** — `npx prisma validate`
4. **Migrations in sync with the schema** (only if `prisma/schema.prisma` changed in this diff, and a local database is running — see the `run-local` skill):
   `npx prisma migrate dev --create-only --name pending_check`
   - "Already in sync" → fine.
   - It creates a migration → the schema change has no migration. Keep it under a meaningful name (follow the `db-migration` skill) or delete the folder if it was only a check.
5. **Production build** (when you touched config, routing, server/client boundaries, `next.config.ts`, the Dockerfile or dependencies): `npm run build`
   - The Docker image runs this; a build failure means the deploy fails after the infra steps.
6. **Smoke test** when a dev or prod server is reachable: follow the `smoke-test` skill.
7. **Security-relevant change?** (auth, redirects, API routes, server actions, uploads, outbound fetches, headers, Bicep) → also run the `pentest` skill's automated probe against a local server.

## Rules worth checking by eye in the diff

- **Next.js 16 is not the Next.js you know.** Before writing framework code, read the guide in `node_modules/next/dist/docs/` (see `AGENTS.md`). `middleware` is `src/proxy.ts`.
- **Redirects** must be built from `appUrl()` / `safeNextPath()` in `src/lib/app-url.ts`, never from `request.url` — behind the Container Apps ingress `request.url` is `https://0.0.0.0:3000`.
- **Data access:** every page, server action and API route calls `requireUser()` / `getCurrentUser()` / `requireAdmin()` from `src/lib/dal.ts`, and organizer code goes through `requireEventAccess()` / `eventAccessOrNull()`. Speaker queries always filter on the session's `userId`.
- **User-supplied URLs** are fetched only through `src/lib/safe-fetch.ts`.
- **Env flags** that come from Bicep: Bicep's `string(true)` is `"True"` — compare case-insensitively or `toLower()` in the template.

## Report

List each step with pass/fail. For a failure include the exact error output and what you changed to fix it. Don't claim "CI will pass" for steps you skipped.
